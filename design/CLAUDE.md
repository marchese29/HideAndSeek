# Design Artifacts

AI-generated design documents and artifacts for the HideAndSeek game.

## Documents

- `2026-02-11-data-model.md` — Server-side data model: transit data, game maps, games, players, location tracking, questions, and exclusion zones.
- `2026-02-14-api-surface.md` — REST API surface organized by player use cases: game lifecycle, location reporting, question asking/answering, and map rendering.
- `2026-02-14-push-notifications.md` — Push notification design: game events → APNS pushes, payload specs, device token lifecycle, and infrastructure sketch.
- `2026-02-15-background-jobs.md` — Background jobs and timers: Celery + Redis for durable game-state timers (hiding→seeking, answer deadlines), resilient push delivery, and task revocation. Includes Docker Compose setup with PostgreSQL.
- `2026-02-16-matching-measuring-questions.md` — Matching ("is your nearest X the same as mine?") and measuring ("are you closer to or further from X?") question types. Covers feature categories (map data vs Google Maps Places API), PostGIS spatial queries, bona fide filtering with hierarchical config, server-side Places proxy, and inventory changes.
- `2026-02-21-distance-conventions.md` — Metric and imperial distance support: convention enum on GameMap, default inventory sets per convention and game size, map-level overrides, data model renames (`distance_m` → `distance`, etc.), conversion boundary for geo math, and API surface changes.
- `2026-02-22-endgame.md` — Original endgame design (Implementation): hiding zones, station codification, endgame exclusion view, candidate stations. Partially superseded by `2026-04-14-endgame-v2.md`.
- `2026-02-26-game-state-split.md` — Game state endpoint redesign: split monolithic `GET /games/{id}` by role (hider/seeker access control) and introduce default-deny question summary. Principles: role = access control only (no response shaping), fixed response shapes, whitelist shared fields.
- `2026-03-01-hider-station-election.md` — Hider station election: voluntary lock-in during hiding, ambiguity handling at hiding→seeking transition, fallback resolution cascade (all-in-radius → any-in-radius → closest pair), nearby-stations and hiding-zone query endpoints. Supersedes Station Selection in `2026-02-22-endgame.md`.
- `2026-03-07-lobby-server.md` — Server-side lobby changes: host-as-player on game creation, auth guards (self-only player updates, host-only start), PlayerColor enum (12 server-assigned colors), 12-player cap, player removal (voluntary leave + host kick + host transfer), real-time lobby updates via SSE over Redis pub/sub, broadcast module design.
- `2026-03-07-lobby-mobile.md` — Mobile lobby experience: screen flow (Home → Create/Join → Lobby), map picker, join code input, lobby UI (player list, self-edit sheet, host controls), SSE via react-native-sse, state management (Zustand for client state + TanStack Query for server state), color mapping, navigation patterns.
- `2026-03-29-gameplay-state.md` — Gameplay state & SSE: role-specific SSE state endpoints (hider-state/seeker-state), dual-channel Redis broadcasting with publish-side visibility, location broadcasting, simplified ACK REST responses, player representations (GamePlayer with location vs RosterPlayer without), question history with exclusion zones, inventory in state.
- `2026-03-29-gameplay-mobile.md` — Mobile gameplay experience: single route with role/phase-dependent rendering, map view (boundary, stops, player pins, total exclusion), SSE-driven Zustand state, question drawer (hider) + question banner (seeker), utility belt, location reporting, stale location indicator, permissions at create/join time.
- `2026-04-03-utility-belt.md` — Utility belt HUD redesign: zone-based layout (state action + timer, toolbelt, info + leave), context strip (hider station name, seeker question timeline with exclusion scrubbing), connection status via timer color, phase/role-specific state action button.
- `2026-04-04-question-flow-mobile.md` — Mobile question flow: seeker question selection via belt takeover (type → parameter → preview → ask), unified Question Banner for both roles (replaces drawer + old banner), boundary-line exclusion previews, thermometer two-phase UX, hider answer/veto/randomize actions, server preview endpoint. Supersedes question UI in `2026-03-29-gameplay-mobile.md` sections 6–7.
- `2026-04-09-tentacles-question.md` — Tentacles question type: seeker picks a POI category, server finds all POIs within a configured distance, hider's answer is the nearest POI (or miss if out of range). Non-binary answer, Voronoi-based exclusion. Point geometry only (for now — HideAndSeek-9ci for complex geometries). Server changes (model, ask/answer, exclusion, events, preview) and mobile seeker experience.
- `2026-04-10-hider-experience.md` — Hider long-game experience: enriched `PlayerLocationEvent` with `candidate_stations` (pre-election stop discovery), `not_in_zone` (zone departure detection), and `computed_answer` (live answer preview). Push-not-poll design — server computes location-derived context on every hider location update. Covers mobile UX for stop selection, hiding zone overlay, departure warnings, and answer preview. Same fields mirrored on `HiderGameStateResponse` for SSE reconnection.
- `2026-04-14-endgame-v2.md` — Endgame v2: proximity tier tracking (4×/2×/1× rings with asymmetric escalation/de-escalation), hider freeze mechanic (edge-triggered departure detection), seeker endgame view (belt utility function, station + question cutoff picker, server-computed inclusion zone), two-party game completion (found claim → hider confirm/reject), more modal (replaces leave button), recap screen, host end game rework (`end_reason`). Supersedes proximity/win-condition sections of `2026-02-22-endgame.md`. Resolves HideAndSeek-vg2.
- `2026-04-19-aws-deployment.md` — AWS deployment architecture: ECS Fargate (server/worker/reconciler), Aurora Serverless v2 (min 0 ACU) with PostGIS, ElastiCache Redis, SNS Mobile Push (replaces direct APNs+FCM), CloudFront → ALB (IPv6-only) → Fargate ingress, IPv6-only egress via Egress-Only IGW (no NAT, no interface endpoints). CDK in TypeScript at `infra/cdk/`. Domain `hideandseek.marchese.dev` via Route 53 (migrated from Squarespace). Service changes: `SnsProvider` replacing `ApnsProvider`/`FcmProvider`, `/healthz`, reconciler singleton deployment, Alembic via one-shot ECS task. Cost: ~$59/mo idle. Corresponds to HideAndSeek-wos.
- `2026-04-21-photo-questions.md` — Photo question type (Draft): seeker requests a photo of a subject from an 18-entry size-gated vocabulary, hider uploads via system photo picker (no in-app camera), seekers accept/reject with auto-accept on a 30s review timer. Lifecycle `asked → submitted → answered` with reject looping back to `asked`; null answer is first-class via the same upload endpoint. Private S3 bucket, server-proxy read/write. `PhotoQueuedEvent` fans out queued uploads so any hider can replace; `PhotoSubmittedEvent` reaches both channels and engages the UI submission lock. `exclusion` stays `NULL`; `total_exclusion` carries forward from the prior question via the existing null-exclusion handler. Dedicated belt palette (`rgb(156, 190, 208)` / `rgb(199, 216, 225)`). Defers game-timer-pause mitigation to a standalone epic. Corresponds to HideAndSeek-z32.
- `2026-04-25-game-timer-pause.md` — Game timer pause mechanic (Draft): future-deadline reframe (store `*_ends_at` / `*_deadline_at` / `*_expires_at` columns, mutate-while-future, freeze-once-elapsed); `Game.paused_at` + `active_pause_reasons` ref-counted set; `seeking_pause_accumulated_sec` carve-out for the count-up belt timer; reconciler filters paused games. Three pause categories (role-targeted banner, host modal, rest-period modal w/ countdown) dispatched on the mobile side from reason set + role + host status. Resolution-action principle: actions that resolve a clock stay live, actions that start a new clock are disabled. First consumer is `photo_question_open` (HideAndSeek-nah). Corresponds to HideAndSeek-m8r.
- `2026-04-29-eventbridge-timers.md` — EventBridge timers (Draft): replace the production polling reconciler with EventBridge Scheduler one-shot `at()` schedules, gated by an env-driven `TimerScheduler` abstraction (`EventBridgeTimerScheduler` in prod, `NoopTimerScheduler` in dev/tests; existing polling reconciler stays for `docker compose`). Target is HTTPS-to-server via an EventBridge API destination, preserving 1s timer granularity and accepting coupling to server uptime since retries absorb deploy gaps. Schedule-before-commit write ordering eliminates the two-write race; no prod backstop sweep on first cut (DLQ + CloudWatch alarm only). Motivation: 1Hz polling pins Aurora Serverless v2 to a non-zero ACU floor and defeats `min=0` auto-pause. Aurora-vs-RDS migration deferred — revisit when `ServerlessDatabaseCapacity` flatlines at non-zero. Corresponds to HideAndSeek-fo0.
- `2026-04-28-question-picker-modal.md` — Question picker modal (Draft): replace the seeker's in-belt parameter picker with a `pageSheet` modal that owns selection, preview, and submission for every question type. Uniform shell with per-family layouts: distance (scrubber + locking points + custom affordance + embedded map preview), category-with-map (current-selection row + sub-sheet picker + embedded map), photo (radio list of subject rows, no map). Submit pinned to bottom; live-reactive active-question gating subscribes to `gameplayStore.active_question` so it disables/enables in real time on `question_asked`/`question_answered`/etc. SSE while the modal is open. Re-ask `ask_count` badge carries to every family. Selection persists across modal opens (open call for distance — see §6); accidental-submit confirm Alert fires only when Submit is the very first picker touch. Removes the seeker banner's preview state, the Ask button, the pre-ask confirm Alert, `gameplayStore.previewQuestion`, and the `PreviewBoundaryOverlay` `'browse'` variant. Resolves HideAndSeek-5zu; implementation tracked under epic HideAndSeek-muo (muo.1–muo.4).

## Conventions

- Store design docs, wireframes, and specifications here.
- Use markdown for text-based design docs.
- Name files with a date prefix: `YYYY-MM-DD-<descriptive-name>.md` (date = creation date).
- Mark documents with a status (Draft / Implementation / Done) and last-updated date.
